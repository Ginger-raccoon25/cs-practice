# Воркшоп lab03 — журнал

## 1. Три состояния проекта
Калькулятор развивался тремя отдельными коммитами:
1. Add addition — сложение
2. Add subtraction — вычитание
3. Add multiplication — умножение
Каждая операция — отдельный коммит: история проекта читается по шагам, любую версию можно посмотреть.

## 2. Сравнение версий и поиск изменений

Команды:
- git log --oneline --stat — список коммитов; у каждого видно, какие файлы менялись и сколько строк добавилось/удалилось.
- git diff HEAD~2 HEAD -- lab03/calc.py — разница между двумя состояниями: показала, что между коммитами «вычитание» и «умножение» в файл добавилась строка print("Произведение:", a * b).
- git show HEAD~1 — один коммит целиком: его сообщение, автор, дата и дифф.

Чем отличаются:
- git log — перечисляет историю (какие коммиты были).
- git show — показывает один конкретный коммит со всеми его изменениями.
- git diff — сравнивает два состояния (коммиты, рабочую папку и индекс) и показывает только строки-различия, без истории.

Поиск изменений:
- git log -S"print" --oneline -- lab03/calc.py — «поиск по изменению»: нашёл коммиты, в которых строки со словом print появлялись или исчезали. У меня это все три коммита — в каждом добавлялся вывод результата.
- git blame lab03/calc.py — напротив каждой строки файла показывает коммит, который её последним менял: сразу видно, кто и когда «родил» каждую строчку.
## 3. Восстановление файла
git restore lab03/calc.py — вернул файл к состоянию ПОСЛЕДНЕГО коммита, стерев несохранённые правки.
git restore --source=HEAD~2 lab03/calc.py — положил в рабочую папку версию из старого коммита (без сложения... точнее, без вычитания и умножения).
git diff показал разницу между этой старой версией и последним коммитом.

Если бы правки были не сохранены в коммит, git restore стёр бы их безвозвратно:
непроиндексированные изменения в Git не хранятся. Поэтому важные правки сначала коммитят.
